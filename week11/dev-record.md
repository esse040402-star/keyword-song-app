## 1. 이번에 구현한 사용자 행동

PRD(키워드 곡함 PRD, 2026-11-09)의 기능 중 핵심 흐름의 앞부분을 골랐습니다.

| --- | --- | --- |
| F1 곡 추가 | 제목(필수)·아티스트(선택)·키워드로 곡 저장 | 구현·확인 |
| F2 키워드 선택·입력 | 미리 있는 키워드 6개 선택 + 쉼표로 직접 입력, 직접 만든 키워드는 다음 추가 화면에 표시 | 구현·확인 |

사용자가 할 수 있는 것: 앱을 열면(곡 0개) "곡을 추가해 보세요" 안내 → 제목과 키워드를 넣고 추가 → 메인에 키워드 폴더가 생기고 곡 수가 표시됨 → 폴더를 누르면 그 키워드의 곡만 보임 → 앱을 다시 열어도 그대로.

## 2. 상태·데이터와 항상 지켜야 할 규칙

### 데이터 (PRD 9장 Song 그대로)

| 필드 | 자료형 | 규칙 | 코드 위치 |
| --- | --- | --- | --- |
| id | int | 기존 최대 id + 1 | `lib/models/song.dart`, `SongStore.addSong` |
| title | String | 앞뒤 공백 제거 후 1자 이상 | `lib/data/song_store.dart` |
| artist | String? | 비면 null | 〃 |
| keywords | List&lt;String&gt; | 선택+직접 입력을 합쳐 공백·중복(영문 대소문자 무시) 제거, 1개 이상 | `SongStore.parseKeywords` |
| createdAt | DateTime | 추가한 시각 | 〃 |

미리 있는 키워드(새벽, 운동, 공부, 드라이브, 비 오는 날, 휴식)는 저장하지 않고 `lib/data/preset_keywords.dart` 상수로 둡니다. 직접 만든 키워드와 키워드 폴더는 곡 목록에서 **계산**합니다(따로 저장하지 않음).

### 상태를 보관·변경하는 위치

- 곡 목록은 `SongStore`(ChangeNotifier) **한 곳**에서만 바꿉니다. 메인 화면·폴더 화면·곡 추가 화면이 같은 객체를 보고, 바뀌면 `ListenableBuilder`가 화면을 다시 그립니다.
- 곡 추가 화면의 입력값(제목·선택한 키워드·오류 표시)은 그 화면의 `State`에만 둡니다(화면 상태).
- 저장은 `SharedPreferences`에 JSON 문자열(`songs_v1`)로 합니다. 곡을 추가할 때마다 전체를 다시 씁니다.
- 상태관리 방식은 패키지 없이 Flutter 기본(ChangeNotifier + ListenableBuilder)을 골랐습니다. PRD의 "상태관리 방식 [미정]"을 이번에 이렇게 정한 것이며, **수업에서 배운 방식과 맞는지 본인 확인이 필요합니다.**

### 불변식(항상 지켜야 할 규칙)

1. 제목이 비었거나 키워드가 0개면 목록을 바꾸지 않는다 → AC2·AC3
2. 메인에 표시한 곡 수(`내 곡 N곡`)와 실제 목록 길이가 같다, 폴더 곡 수 = 그 키워드가 붙은 곡 수 → AC1·AC7
3. 한 곡에 같은 키워드가 두 번 붙지 않는다(공백·대소문자 무시) → AC4
4. 곡이 0개인 키워드는 폴더로 만들지 않는다
5. 저장 데이터를 읽지 못하면 앱이 멈추지 않고 안내 후 빈 목록으로 시작한다

## 4. 실패·미실행·미완료와 다음 작업

### 관찰한 문제

- **추가 버튼 첫 클릭이 먹히지 않은 적이 1번 있음 (원인 미확인)**: 브라우저에서 AC4를 확인할 때, 직접 입력란에 입력한 직후 '추가'를 한 번 눌렀지만 화면이 그대로였고, 한 번 더 누르자 추가됐습니다(곡이 두 번 들어가지는 않음). 입력란 포커스 해제나 오류 문구가 사라지며 버튼 위치가 움직인 것이 원인일 수 있으나 **확인하지 않았고** 재현도 해 보지 않았습니다.
- `flutter analyze`가 한글 경로에서 종료되는 문제 (위 표). 이 폴더에서 `dart analyze`와 영문 경로 사본의 `flutter analyze`로 대신 확인했습니다.

### 미실행

- Android 실행 (PRD의 실행 플랫폼은 여전히 미정, 이번에는 웹만 확인)

1. F3 곡 키워드 수정 (AC6) — 메인 폴더 곡 수가 바뀌는지 확인
2. F7 여러 키워드 검색 — 모두 일치 / 일부 일치 (AC12·AC13)
3. 내장 곡 목록 100곡 + F8 추천 (AC14·AC15) — 곡 목록 작성에 시간이 걸리므로 먼저 시작

5. F10 붙여넣기, F11 곡 삭제

### 문서 정리가 필요한 것

- 앱 이름: PRD와 9주차 `topic.md`는 '키워드 곡함', 앱 화면 제목과 발표 장표는 '키워드 플레이리스트' → 이름을 하나로 정하고 문서를 맞출 것
- 9주차 `topic.md`·`analysis.md`는 아직 PRD(플레이리스트·추천·AC 17개)에 맞게 고치지 않음
- PRD AC1의 "입력란 초기화"는 곡 추가를 **별도 화면**으로 만들면서 "추가 후 메인으로 돌아가고 안내 표시"로 바뀜 → PRD 문구 수정 필요
- 미리 있는 키워드 6개는 9주차 초안 그대로이며 **본인이 확정하지 않음**. 키워드 최대 개수·길이도 정하지 않아 현재 제한 없음
